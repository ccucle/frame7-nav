# FORMDAY Connect 5차 개발 — 추가 등록 기능

작성: 2026-11-24 (Asia/Seoul). Connect 소스 버전 0.4.0이며 기존 FORMDAY 사이트 버전은 v0.6.0 그대로다.

## 구현 결과

| 요청 예시 | 구현한 동작 | 제한 |
| --- | --- | --- |
| 월요일에 가슴루틴1 등록해 | 기존 루틴 ID와 정확한 날짜·시각으로 캘린더 웨이트 계획을 추가 | 미완료 계획이며 실제 IRON 운동 세션을 시작하거나 완료하지 않음 |
| 이 루틴들로 프로그램 등록해 | 기존 루틴을 참조하는 요일형/순환형 IRON 프로그램 추가 | 기존 프로그램과 운동 기록 수정·삭제 없음 |
| 오늘 식단 등록해 + 사진 | ChatGPT가 해석한 음식·양을 구조화해 식사 기록 추가 | 서버 이미지 인식·원본 사진 저장 없음. 모호한 음식/양은 저장 전 확인 필요 |

기존 6개 읽기 도구를 유지하고 미리보기 3개와 저장 도구 1개를 추가했다. 프로그램은 루틴 조회 결과에서 확인할 수 있다. 식단 조회는 현재 사이트의 amount/basisUnit과 영양 기준량·출처·메모를 반환하며, 한국 시간 기준 오늘을 사용한다. 사진 추정치는 미검증으로 표시하고 모르는 영양소를 0으로 채우지 않는다.

## 안전장치

- 기본 쓰기 비활성. 서버의 FORMDAY_ENABLE_APPEND=true와 새 formday:append OAuth 동의를 모두 요구한다. 읽기 토큰은 자동 승격되지 않는다.
- 승인 페이지는 서버에 저장된 승인 요청에서 권한을 읽는다. URL 값을 바꿔 쓰기 동의를 읽기 화면으로 위장할 수 없다.
- 미리보기는 쓰지 않는다. 서버 서명으로 UID·대상 MCP·추가할 항목·원본 payload 해시·revision·updateTime을 묶는다. 새 쓰기 유효기간은 10분이다.
- 저장 시 최신 원본을 다시 읽고 원본 일치 여부를 검사한다. 실제 Firestore commit에도 updateTime 조건을 넣어 조회 이후의 경쟁 변경을 차단한다.
- 기존 JSON 항목과 부가 속성을 보존하고 새 항목만 추가한다. 기존 스냅샷이 없거나 캘린더 schemaVersion 3이 아니면 쓰지 않는다. 전체 결과는 550KB 이하로 제한한다.
- 통신 응답이 유실되어도 같은 previewToken을 다시 사용하면 동일 ID를 확인해 중복 등록을 막는다. 만료 후에도 이미 저장된 동일 항목 확인은 가능하지만 새 쓰기는 불가능하다. 사용자가 삭제/수정한 항목을 재생성/복원하지 않는다.
- 새로운 미리보기는 새 작업이다. 서로 다른 미리보기 사이의 의미상 중복 방지는 구현하지 않았다. 결과 불명 상태에서 새 미리보기로 즉시 재등록하지 말고 기존 토큰/조회 결과로 확인해야 한다.
- 미리보기 토큰은 서명된 base64 데이터이며 암호화되지 않는다. 개인 데이터가 포함되므로 로그·공개 링크·GitHub 등에 저장하지 않는다.
- Firestore는 본인 Firebase ID 토큰으로 접근한다. 관리자 권한으로 건강 기록을 쓰지 않는다. 기존 보안 규칙은 변경하지 않았다.

Firestore 원자적 commit 및 updateTime 조건은 [공식 Write 문서](https://firebase.google.com/docs/firestore/reference/rest/v1/Write)와 [commit 문서](https://firebase.google.com/docs/firestore/reference/rest/v1/projects.databases.documents/commit)에 맞췄다. 실제 배포된 규칙의 허용 여부는 아직 검증하지 않았다.

## 검증 범위

로컬 전체 67개 테스트 통과: 기존 47개 + 신규 20개. 실제 MCP SDK 호출, 로컬 HTTP OAuth 연결, 합성 RSA 토큰을 사용한다. 외부 인증 서버·Firestore·토큰 저장소는 모의 구현이다.

신규 검증은 세 종류 추가, 원본 보존, 사이트 정규화 호환, 등록 후 조회, 사진 추정/미확인 영양정보, 동일 요청 재시도, 동시 저장, 조회 후 경쟁 변경, 삭제 후 재생성 차단, UID/대상/서명/만료 검증, 크기/형식 제한, 쓰기 권한 거부, OAuth 동의 화면·범위·기능 플래그, 한국 날짜 경계를 포함한다.

프로그램 요일 필드가 모든 요일을 요구하던 초기 검증 오류를 테스트에서 발견하고 선택한 요일만 받도록 수정했다. 최종 로컬 테스트는 모두 통과했다. CI 결과는 PR #7에 별도로 기록한다.

## 배포·실사용 상태

**서버 배포·ChatGPT 설치·실제 계정 연결은 아직 완료되지 않았다.** 운영 기록을 조회하거나 수정하지 않았고, Firebase 규칙·인증 설정·기존 사이트 파일도 변경하지 않았다. 새 무료/유료 서비스 및 결제 설정 변경도 없다.

4차 검토에서 식별한 OAuth 발급 원자성·철회·동시 갱신·요청량 제한·만료 비밀정보 정리 문제는 이번 기능 구현으로 해결됐다고 간주하지 않는다. 격리된 인증 저장소, IAM, 비밀키, HTTPS 호스트, Google 브라우저 로그인, 실제 Firestore 규칙 검증도 남아 있다. 따라서 쓰기는 기본 비활성이고 이 PR은 검토용 초안이다.

사이트에서 원격 추가 항목을 보려면 본인 계정으로 클라우드 내려받기가 필요하다. 사이트가 다른 기기의 변경을 자동 표시하도록 수정하지 않았다. 로컬 미동기화 기록이나 진행 중인 IRON 세션이 있으면 충돌/내려받기 제한을 먼저 해결해야 한다. 루틴 일정은 미리보기 시점의 목표 복사본이며, 이후 원본 루틴을 수정해도 자동으로 변경되지 않는다.

아이폰 지원 경로는 사용자 측 모바일 세션에서 확인할 작업으로 남긴다. 이 코드의 완성이나 PC 연결만으로 아이폰 사용이 가능하다고 보고하지 않는다. [4차 보고서](PHASE4-REVIEW.md)의 플랫폼 제약 및 배포 장애 요소를 함께 참고한다.
