# FORMDAY Connect 4차 개발 검증

확인일: 2026-11-24, Asia/Seoul. 결론: 코드 보완 및 모의 통합 검증 완료, 운영 배포·실제 계정 연결·PC/iPhone 공통 사용은 미완료.

## 확인한 원본과 테스트

- [PR #7](https://github.com/ccucle/frame7-nav/pull/7): 공개 저장소의 열린 초안. 기준 head `6e36af19de7a885d47e9a1c10b39977ea2578794`, base `2ed96f7596f7059aca567e389ba6e960d2855445`.
- [기존 Actions 실행](https://github.com/ccucle/frame7-nav/actions/runs/45202576196): 로그에서 Node 22.23.5, 37건 통과·0건 실패 확인. 실행 대상은 해당 head와 base의 검토용 병합 커밋 `86fa9ccb51c52e0a57749d52e706152c759d3285`였다. 운영 브랜치 병합이 아니다.
- 원본 head를 로컬 Node 24.21.0에서 다시 실행: 37건 통과.
- 추가 회귀 검사로 원본에서 5건 실패를 재현한 뒤 수정. 최종 로컬 실행: **47건 통과, 실패·건너뛰기 0건**.
- 실제 Node HTTP 서버를 127.0.0.1에 열어 OAuth 발견, 승인 쿠키/CSRF, 코드 교환, 만료, 갱신, 재사용 거부 및 실제 MCP SDK의 initialize/list/call을 실행했다. 자체 RSA 키로 서명한 가상 Firebase 토큰을 검증했다.
- 여섯 도구 중 운동·식단·체중·캘린더에서 실제 예상값을 대조했다. 워밍업 제외 운동량 600kg, 식사 항목, 체중 82.4kg, 일정 조회 및 샘플 제외는 모두 **테스트용 값**이다.
- Google/Firebase 응답과 Firestore 저장소는 테스트 대역이다. 실제 Google 팝업, 브라우저 쿠키 정책, 운영 Firestore 트랜잭션·보안 규칙, 외부 HTTPS, ChatGPT 클라이언트는 검증하지 않았다.
- 패키지 잠금 파일을 추가하고 CI를 `npm ci` 및 Node 22/24로 구성했다. `npm audit --omit=dev` 결과 알려진 취약점 0건. 이것은 애플리케이션의 보안 인증이 아니다.

## 수정한 내용

| 원본에서 확인한 문제 | 4차 변경 |
| --- | --- |
| Secure Token 응답의 숫자 프로젝트 번호를 다른 프로젝트로 거부 | 기존 공개 앱 설정의 번호 `188014722362`와 프로젝트 ID를 명시적으로 허용. 실제 JWT 서명·aud·iss·UID 검증은 유지 |
| 갱신 요청의 다른 resource 또는 write scope를 무시 | 기존 grant와 불일치하면 토큰을 소비하기 전에 거부. 원본도 발급 권한은 읽기로 고정되어 있었으며 쓰기 권한 상승을 재현한 것은 아님 |
| 로그인 페이지 CSP가 Firebase 인증 iframe을 차단 | 지정된 Firebase 인증 도메인의 frame과 Google 인증 스크립트만 허용. 실제 브라우저 로그인 성공은 별도 검증 필요 |
| 승인 경로가 내부 오류 문구를 그대로 반환 | 고정된 공개 오류로 교체하고 가상 비밀문구가 노출되지 않는지 검사 |
| OAuth 저장용 Admin SDK가 기존 건강 기록 프로젝트를 사용 | 별도 프로젝트 설정 필수화. `healthy-df79f` 프로젝트 또는 그 서비스 계정이면 시작 차단 |
| 브라우저 로그인 정보가 기본 영구 저장 방식 사용 | 메모리 저장 및 승인 종료 시 로그아웃으로 변경 |

PKCE verifier의 유효한 `.`·`~` 문자도 지원하도록 수정하고, S256 challenge 길이를 43자로 제한했다. URL 내 사용자정보를 거부한다. HTTP 서버를 독립적으로 테스트할 수 있게 분리하고 외부 Host, 이중 슬래시 경로, 64KiB 초과 요청 거부를 검증했다.

## PC와 iPhone의 지원 범위

OpenAI의 [맞춤 MCP 연결 공식 안내](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt)는 모바일 연결 질문에 **“No - web only.”**라고 명시한다. PC 웹은 계정·워크스페이스 권한에 따라 연결할 수 있고, Pro의 읽기/가져오기 연결도 안내한다. 사용자의 ChatGPT 요금제와 실제 메뉴 접근 권한은 확인하지 않았다.

반면 [일반 플러그인 공식 안내](https://help.openai.com/en/articles/20001256-plugins-in-chatgpt)는 웹·데스크톱·모바일에서 디렉터리를 제공하며 기능별 지원 환경이 다르다고 설명한다. 따라서 **아이폰에서 모든 플러그인이 불가능한 것은 아니다.** 현재 FORMDAY가 택한 직접 등록 방식의 사용자 정의 MCP를 아이폰에서 지원한다고 볼 근거가 없다. PC에서 설치하면 아이폰에서도 작동한다는 보장도 없다.

| 목표/환경 | 확인 결과 | 남은 조건 |
| --- | --- | --- |
| 네 종류의 FORMDAY 기록 조회 코드 | 모의 통합 검증 통과 | 실제 본인 기록과 값 대조 |
| PC ChatGPT 웹 | 플랫폼상 조건부 연결 가능 | 서버·OAuth 운영 준비, 계정 권한, 실제 설치·조회 |
| iPhone ChatGPT 앱의 직접 등록 맞춤 MCP | 공식 안내상 웹 전용 제약 | 지원되는 배포 경로 확보 및 실제 기기 검증 |
| PC·iPhone 공통 사용 | 미충족 | 두 환경에서 동일 계정으로 네 데이터 종류 조회 확인 |

공식 디렉터리 배포나 Sites 기반 플러그인은 별도로 조사할 후보이며, 단순 포장으로 현재 MCP의 모바일 제한이 해소된다고 판단하지 않는다. 별도 웹 AI 화면은 iPhone ChatGPT 앱 내부 사용이라는 요구를 충족하지 않는다.

## 배포 판정: 아직 배포하지 않음

사용자가 확인한 Render 작업공간에서 기존 서비스 목록만 조회했다. FORMDAY 정적 사이트는 `fitplan-site-20261123` 브랜치, 자동 배포 꺼짐 상태였고, 별도의 FORMDAY Connect 서버는 없었다. 다른 기존 서비스도 변경하지 않았다. 계정 결제수단·잔여 사용량·지출 제한은 확인하지 않았다.

1. **격리된 OAuth 저장소가 없음.** 이번 변경은 기존 Firebase에 인증 문서를 쓰지 않게 하는 시작 차단이다. 별도 프로젝트/저장소는 생성하지 않았다. 프로젝트 ID가 다르더라도 해당 서비스 계정에 기존 프로젝트 IAM 권한이 없는지는 별도 확인해야 한다. Firebase Admin은 [Security Rules를 우회한다](https://firebase.google.com/docs/firestore/security/rules-conditions).
2. **토큰 수명 관리가 미완성.** `oauth-core.mjs`의 `issue()`는 grant/access/refresh를 별도 쓰기로 생성한다. 코드 소비 후 일부 저장 실패 시 재인증이 필요할 수 있다. 갱신 시 새로운 grant를 만드는 구조, 요청별 Firebase 갱신과 자격정보 저장은 동시 요청·부분 장애 검증이 필요하다. 전체 grant 철회, 재사용 감지 후 토큰 계열 철회, 만료 암호문 정리도 구현해야 한다.
3. **남용·비용 방어 미완성.** 인증 시작과 토큰/MCP 요청에 대한 요청량 제한이 없다. 익명 승인 시작으로 저장량을 늘릴 수 있다. 만료 flow/code와 장기 자격정보 보존·삭제 정책을 확정해야 한다. 무료 TTL 삭제나 영구 메모리 저장소로 해결됐다고 간주하지 않는다.
4. **실제 Google 로그인 준비 미완료.** HTTPS 호스트, Firebase Authorized domains 및 정확한 ChatGPT callback/CIMD 설정이 필요하다. 현 메타데이터는 issuer 응답 지원을 false로 표시하므로 새 연결의 callback-ID 방식으로 테스트했다. [OpenAI 인증 문서](https://developers.openai.com/plugins/build/auth)에 따라 관리 화면의 정확한 URI를 확인해야 한다. 비밀키는 채팅·저장소에 넣지 않는다.
5. **기존 계정 보호의 추가 조건.** Firebase Google 팝업은 [첫 로그인 시 새 Firebase 사용자를 생성할 수 있다](https://firebase.google.com/docs/auth/web/google-signin). 기존 계정 선택 안내만으로 이를 막지는 못한다. 계정 변경 금지 조건을 만족하는 최초 로그인 방지 방식을 마련하기 전 운영 로그인을 실행하지 않는다. 기존 안내의 ‘계정은 변경되지 않았다’는 일괄 오류 문구를 제거했다.
6. **무료 서버도 비용 보장 불가.** [Render Free 공식 문서](https://render.com/docs/free)는 유휴 중단, 재시작 시 로컬 파일 소실, 결제수단이 있을 때 대역폭/빌드 초과 과금을 안내한다. 현재 계정의 비용 차단을 확인하지 못했으며 유료 서비스는 물론 새 무료 서비스도 생성하지 않았다.
7. **iPhone 경로가 제품 출시 장애 요소.** 서버가 안전해져도 플랫폼 지원 문제가 별도로 남는다. PC만 연결된 상태를 완성으로 처리하지 않는다.

## 다음 단계의 통과 기준

먼저 코드에서 토큰 발급의 원자성·철회·동시 갱신·요청량 제한을 보완하고, 운영 기록과 분리된 테스트 환경에서 재시작·부분 실패·재사용 시나리오를 검증한다. 이후 비용 상한과 독립 저장소의 권한이 확인된 환경에서 HTTPS 및 브라우저 인증을 검증한다. 실제 본인 계정으로 네 종류의 기록을 대조하되 원본 문서 수정·규칙 변경은 하지 않는다. 마지막으로 공식 지원 경로를 통해 PC 웹과 iPhone 앱 양쪽에서 반복 조회·재로그인·연결 해제를 검증한다.

이번 작업에서는 운영 FORMDAY v0.6.0 파일, Firebase 데이터·규칙·Authorized domains, 사용자 계정, 결제 설정을 변경하지 않았다. 개발 브랜치의 Connect 코드·테스트·CI·문서만 변경했다.
