# Connect original meal photo — development adapter, not deployed

This branch extends historical Connect development source 3c7ae8970487abf4f23405576da99bfa24f21c06 (PR #10, not verified as the live Sites implementation). It changes no main website or existing authentication. The module implements a server-only, dependency-injected photo attachment core using the existing calendar schema and photo document format. The authenticated host must provide the actual user-bound upload ingress, photo-specific consent, real local image decoder, and owner-scoped transactional storage adapter. It must map the exact authenticated user's path `users/{uid}/formday_meal_photos/{mealId}` and request-time server timestamp; enforce current published Firestore Rules; and never use Admin bypass, client-supplied UID, raw credentials, or a second hosting service. The returned status and SHA-256 are confirmed only by server readback.

The core is append-if-absent, never replace/delete; same photo and meal ID retry is idempotent. The meal must already have been committed and independently confirmed by the existing meal workflow. No calendar/IRON/Buddy writes. If upload is unavailable, do not pretend it succeeded. Existing meal append authorization by itself does not authorize an original photo; use the explicit user's attachment intent through the existing authenticated session. Do not pass raw photos in chat tool arguments or logs.

Release gate: obtain the actual existing Sites source, implement and test the authorized binary file bridge + trusted adapter, compare active Rules and verified account, test synthetic data end-to-end with existing photo pilot, verify real cross-device reflection, preserve strict KRW0 budget.
