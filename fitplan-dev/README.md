# FORMDAY v0.4.0-rc.1 — 계정 저장 후보

이 폴더는 개발 문서와 회귀 테스트용입니다. 현재 운영 정적 사이트는 `fitplan/`만 게시하며, 브라우저 저장 방식의 **v0.3.0**입니다.

`fitplan-accounts-20261123` 브랜치는 로그인·사용자별 서버 저장·기기 간 동기화의 **배포 전 후보**입니다. 계정 화면과 API를 구현했지만 새로운 유료 서버/DB는 생성하지 않았습니다. 사용자의 **추가 운영비 0원** 결정에 따라 유료 Render 배포안은 철회했습니다. 이 브랜치는 개발 결과를 보관하며, 운영 사이트에 계정 기능을 활성화하지 않습니다.

## 이번 후보의 계정 기능

- 아이디·비밀번호 가입/로그인, 한 번 표시하는 복구 코드와 비밀번호 복구.
- 기존 브라우저 기록과 계정별 캐시 분리, 로그인 후 사용할 기록의 명시적 선택.
- 기기 저장 후 서버 업로드, 서버 버전 충돌 표시, 같은 작업 번호로 안전하게 재시도.
- 다른 기기 기록을 `지금 동기화`로 불러오기, 미전송 기록을 보존한 동일 계정 재로그인.
- PostgreSQL 저장, Secure/HttpOnly 쿠키, Origin/CSRF/예상 사용자 확인, 요청 크기/빈도 제한.

추가 운영비 0원 결정·무료 대안·현재 한계는 [ACCOUNTS-ROLLOUT.md](ACCOUNTS-ROLLOUT.md)에 정리했습니다. [QA-0.4.md](QA-0.4.md)에 자동 테스트 **133개 통과**와 검증 한계를 기록했습니다. 실제 배포가 완료된 것으로 읽지 않도록 현재 운영 버전과 후보의 상태를 구분합니다.

## v0.3.0 식단 기능

- 공식 USDA FoodData Central의 SR Legacy 2018-04 전체 7,793개 식품을 검색합니다. 원문 이름을 유지하고 검토한 80개 이름에 한국어 표시를 추가했습니다. 나머지 7,713개는 영문 이름으로 검색합니다.
- 한 식사에 여러 음식을 추가하고 섭취량에 비례해 열량·단백질·탄수화물·총 지방·불포화지방을 계산합니다. 실제 일일 섭취량에는 완료한 식사만 합산합니다.
- 포장지에 적힌 제품별 기준량(g, ml, 회분)과 영양성분을 직접 등록하고 내 식품·즐겨찾기에서 재사용합니다. g와 ml를 서로 변환하지 않습니다.
- 식사에는 등록 당시의 식품 정보를 복사해 저장합니다. 이후 내 식품의 영양성분을 수정하거나 삭제해도 과거 기록의 수치가 바뀌지 않습니다.
- 출처, 데이터 기준월, 식품 원문 이름, FDC ID를 표시합니다. 불포화지방을 확인할 수 없는 523개 식품은 0g으로 처리하지 않으며, 일부 값만 합산한 경우 누락 사실을 표시합니다.
- 식품 목록은 식사 편집창을 열 때 불러옵니다. 실패하면 재시도할 수 있으며, 이미 저장한 식품과 기록은 계속 사용할 수 있습니다.

## 이전 단계에서 유지한 기능

- 웨이트 한 일정에 여러 종목과 종목별 세트를 기록합니다.
- 세트마다 중량, 횟수, RPE(선택), 워밍업 여부와 완료 여부를 저장합니다.
- 종목별 최근 실제 수행 기록을 보여주고 세트 추가·복제·삭제를 지원합니다.
- 완료한 본 세트의 중량 × 횟수만 운동량에 합산합니다. 워밍업은 완료 세트 수에는 포함하지만 운동량 합계에는 포함하지 않습니다.
- 60·90·120초 휴식 타이머에 일시정지·재개·초기화를 제공합니다.
- 반복 일정의 기본 계획과 날짜별 기록을 분리합니다. 날짜별 수정은 해당 날짜에만 반영하고, 기본 계획을 바꾸어도 저장된 실제 기록은 유지합니다.
- 반복 종료일, 특정 날짜만 삭제, 한 단계 되돌리기, 일정·운동 검색, 겹치는 시간대 일정의 나란히 표시를 추가했습니다.
- 체중은 측정 완료된 실제 기록만 그래프와 최근 측정에 반영합니다. 반복 체중 일정은 이전 측정값을 다음 날로 복사하지 않습니다.
- 유산소 운동 강도를 저장합니다. 식단의 칼로리·탄수화물·단백질·총 지방·그중 불포화지방 계산은 유지합니다.

## 저장과 이전 버전 호환

`formday_calendar_proto_v1` 저장 키를 그대로 사용합니다. 기존 단일 종목 기록을 종목·세트 구조로 변환하고, 반복 완료일 목록을 날짜별 기록으로 변환합니다.

변환 전에 없던 실제 기록을 추정해 만들지 않습니다. 기존 반복 데이터에는 날짜마다 다른 중량/측정값이 보관되지 않았기 때문에, 변환은 기존에 저장된 값과 완료일로만 이루어집니다. 기존 파일 자체가 잘못된 경우 원본을 보존하고 복원을 안내합니다.

저장은 유효성 검사 → 현재 버전 확인 → 직전 원본 보관 → 쓰기 순서입니다. 저장 실패 때 성공 알림을 띄우거나 편집창을 닫지 않습니다. 다른 탭이 먼저 저장하면 오래된 입력으로 덮어쓰는 대신 최신 기록 불러오기를 안내합니다. `localStorage`는 서버 트랜잭션이 아니므로 완전한 동시성 보장을 제공하지 않습니다.

백업은 `app: formday`, `version: 3`을 사용하는 JSON입니다. v1·v2 백업도 유효성 검사 후 가져올 수 있습니다. 기존 단일 식품 식단은 당시 영양값을 유지하는 식품 스냅샷으로 변환합니다. 내 식품과 즐겨찾기도 백업에 포함합니다. 지원하지 않는 버전, 잘못된 날짜/시간/수치, 중복 ID, 손상된 파일은 거부하고 기존 기록을 유지합니다. 가져오기는 현재 데이터를 대체하는 작업이므로 화면에 명시적인 확인이 있습니다.

v3 저장 후에는 v0.2.1 코드로 단순히 되돌려 최신 기록을 읽을 수 없습니다. 이전 코드가 v3를 거부하므로 복구에는 배포 전 원본 백업 또는 별도 하향 변환이 필요합니다. 최신 기록이 있는 브라우저에서는 현재 버전의 내보내기로 먼저 백업합니다.

## 범위와 제한

- 현재 운영 v0.3.0에는 계정과 서버 저장이 아직 연결되지 않았습니다. 이 후보의 계정 기능은 별도 활성화가 필요합니다. Google Calendar 연동과 실제 AI API는 포함하지 않습니다.
- 비로그인 기록은 사용하는 브라우저에 저장됩니다. 계정 기록도 동기화 전에는 이 기기 캐시에만 있으므로 내보내기로 백업할 수 있습니다. 브라우저 데이터 삭제는 미전송 기록을 지울 수 있습니다.
- 공식 식품 목록은 USDA SR Legacy의 2018년 최종 자료입니다. 모든 식품이나 최신 국내 브랜드 제품을 포함하지 않습니다. 생것과 조리한 음식, 품종이 다르면 별도 항목이므로 원문과 조리 상태를 확인해야 합니다. 기존 41개 샘플의 영양값은 새 검색 목록에 섞지 않고 기존 기록에만 출처를 표시해 보존합니다.
- 직접 등록한 제품은 사용자가 입력한 표시사항입니다. 공인 검증 표시를 붙이지 않습니다. 바코드 자동 조회, 음식 사진 분석, 식약처 최신 국내 제품 데이터 연동은 아직 없습니다.
- 한 식사 최대 50개 음식, 내 식품 500개, 즐겨찾기 1,000개를 지원합니다. 검색 결과는 페이지당 50개를 표시합니다.
- 일정 5,000개, 날짜별 반복 기록 20,000개, 한 일정의 운동 30종목, 종목별 50세트를 지원합니다. 초과 데이터는 조용히 잘라내지 않고 명시적으로 거부합니다.
- 월 보기에서 단일 일정을 다른 날짜로 드래그할 수 있습니다. 반복 일정은 편집창에서 범위를 선택합니다. 주·일 보기의 드래그 및 리사이즈는 아직 없습니다.
- 자정이 넘는 일정은 두 날짜로 나누어 등록합니다.
- 기존 화면의 배치와 색상은 유지하면서 긴 운동 편집창, 모바일 입력 크기, 키보드 포커스 이동을 개선했습니다.

## 검증 실행

Node 24의 내장 테스트 기능을 사용합니다. 프런트엔드 단위 테스트에는 추가 설치가 필요하지 않으며, 서버 SQL 테스트에는 아래 개발 의존성을 설치합니다.

```sh
npm ci --prefix fitplan-server
node --test fitplan-dev/*.test.cjs
```

검증 범위는 구버전 변환, 반복 날짜 독립성, 완료 운동량, 실제 체중 집계, 저장 실패·충돌·복원, 미저장 입력 보존, 기본 계획 편집, 타이머 보정에 더해 식품 단위별 비례 계산, 결측값 표시, 제품 수정과 과거 기록의 독립성, 사용자 식품·즐겨찾기 백업입니다. DOM 어댑터 기반 테스트는 실제 브라우저·모바일 렌더링을 대신하지 않습니다.

## 식품 자료와 재생성

원본 다운로드 주소, ZIP 해시, 영양성분 필드, 한국어 이름 매핑, 결측·불일치 처리 정책은 `source-manifest.json`에 기록했습니다. `build-catalog.py`는 외부 패키지 없이 공식 ZIP을 내려받아 배포용 JSON을 생성합니다. 원본 데이터는 CC0이며 출처를 표시합니다.

```sh
python fitplan-dev/build-catalog.py --check
```

불포화지방은 단일불포화지방산과 다중불포화지방산의 합입니다. 둘 중 하나가 없는 518개와 원본 합계가 총 지방보다 0.1g/100g을 초과하는 5개는 `null`입니다. 5개 불일치 항목은 원본 값과 근거를 manifest에 유지합니다. 차이가 0.1g 이하인 원본 반올림 차이는 값을 바꾸지 않습니다. 직접 입력 제품은 불포화지방이 총 지방을 초과하면 저장하지 않습니다. 열량은 원본 kcal를 사용하며 탄단지 4/4/9로 다시 계산하지 않습니다. 목표 열량은 기존 사용자 목표 탄단지의 4/4/9 합계입니다.

## 다음 구현 순서

1. 무료 범위에서 현재 브라우저 저장 버전을 유지·개선합니다. 계정 동기화는 접근 가능한 무료 환경과 인증 수단을 확인한 뒤 전환합니다.
2. 주간 통계와 계획 비교는 우선 비용 없는 계산 기능으로 개선합니다. 규칙 기반 계산을 실제 AI 분석으로 표시하지 않으며 유료 AI API를 연결하지 않습니다.
3. Google Calendar 연동은 별도 계정 승인과 동기화 범위를 정한 뒤 연결합니다.

## 0.2.1 화면 검증 반영

긴 운동 편집창에서 바깥 모달이 함께 스크롤되던 문제를 수정해 제목과 저장 버튼을 고정했습니다. 입력을 바꾸지 않은 상태에서 반복 수정 범위만 선택할 때 불필요한 변경 취소 확인이 뜨지 않도록 조정했습니다.
