# FORMDAY v0.3.0 — 식품 데이터와 식사 기록

작성일: 2026-11-23 (Asia/Seoul)

## 제공 기능

- USDA FoodData Central SR Legacy 2018-04 전체 7,793개 식품 검색. 검토한 한국어 이름 80개와 영문 원문 전체를 제공한다.
- 한 식사에 최대 50개 음식을 추가하고 식품별 기준량으로 비례 계산한다. g, ml, 회분은 각각 같은 단위끼리만 계산한다.
- 제품 영양성분을 직접 등록·수정·삭제하고 즐겨찾기로 재사용한다. 직접 입력 제품은 열량·단백질·탄수화물·총 지방이 필수이며 불포화지방은 선택이다.
- 식사 기록은 식품 정보의 독립된 사본을 보관한다. 보관함의 제품 변경은 이전 기록을 바꾸지 않는다.
- 일일 섭취 합계에는 완료한 식사만 포함한다. 미확인 영양소는 0으로 간주하지 않는다.
- v1·v2 기록과 백업은 v3로 이전한다. 기존 41개 샘플 식품의 수치와 섭취량은 당시 값 그대로 유지하고 기존 샘플임을 표시한다.

## 자동 검증

Node.js 내장 테스트 **67개 통과**:

- 앱 통합 17개: 기존 기록 표시, 완료 식사만 합산, 미확인·부분 합계, 백업, 저장 실패, 카탈로그 재시도와 캐시, 빈 식사 유형 전환.
- Core 12개: 구버전 변환, 반복 날짜 독립성, 기록 집계, 저장 충돌과 복구.
- 식사 편집기 11개: 입력 보존, 제품 수정과 기록의 독립성, 저장 실패, 제품 폼 왕복 보존, 검색 페이지, 영문 검색어 순서와 구두점, 즐겨찾기/삭제 실패, HTML 이스케이프, 비동기 해제.
- 영양 계산 12개: 41개 이전 식품, 단위별 계산, 결측값, 출처, 유효성 검사, 사용자 식품과 즐겨찾기, 반복 기록.
- 웨이트 15개: 세트·완료·기록·타이머 등 기존 동작 회귀 검사.

테스트는 DOM 어댑터를 사용하므로 실제 브라우저 렌더링 검증과 구분한다. 배포 후 브라우저 확인 결과는 `QA-0.3.md`에 별도 기록한다.

## 저장과 운영 제한

사용자 기록과 내 식품·즐겨찾기는 이 브라우저에 저장한다. 로그인, 서버 저장, 기기 간 동기화, Google Calendar 연결 및 실제 AI API는 아직 연결하지 않았다. 원본 카탈로그는 사이트에서 같은 출처의 JSON으로 불러오며 사용자 기록을 USDA로 전송하지 않는다.

이 단계는 기존 사이트의 `fitplan-site-20261123` 브랜치와 `fitplan/` 게시 폴더를 사용한다. 다른 앱의 루트 파일을 변경하지 않는다. 배포는 수동이며 자동 배포를 켜지 않는다.

저장 형식은 v3다. v3 저장 이후 이전 v0.2.1 앱으로 단순 롤백하면 최신 기록을 읽을 수 없으므로, 코드 롤백 전 원본 백업과 형식 호환성을 확인해야 한다.
