## 실제 브라우저 확인

데스크톱 Chrome에서 기존 데이터가 있는 동일한 브라우저로 확인했다. 별도의 iPhone/Safari 실기기 검증은 수행하지 않았다.

1. 버전 표시가 v0.3.0이며 기존 완료 샘플 두 식품의 열량 365.5 kcal가 유지됨을 확인했다. 오른쪽 영양 리포트도 365.5로 표시되고 기존 샘플 출처가 표시된다.
2. 빈 날짜에 검증용 식사 하나를 만들었다. 공식 목록 전체 7,793개가 로드되었다.
3. `chicken breast` 검색에서 원문 단어 순서가 다른 생 닭가슴살과 구운 닭가슴살을 찾았다. 검색 결과는 33개였다.
4. 구운 닭가슴살 150g과 바나나 100g을 추가했다. 합계는 336.5 kcal, 단백질 47.6g, 탄수화물 22.8g, 지방 5.7g, 불포화지방 3.1g으로 표시되었다.
5. 검증용 제품을 45g당 180 kcal, 단백질 20g, 탄수화물 15g, 지방 5g, 불포화지방 미입력으로 저장했다. 90g을 추가하자 360 kcal가 더해져 식사 합계 696.5 kcal가 되었다. 불포화지방은 부분 합계와 누락 1개로 표시되었다.
6. 즐겨찾기를 저장한 뒤 미완료 식사를 등록했다. 일일 섭취량은 0 kcal였다. 완료로 바꾸자 696.5 kcal가 반영되었다.
7. 새로고침 후 동일 날짜에서 696.5 kcal 기록이 유지되고, 즐겨찾기에 45g당 180 kcal 제품이 남아 있음을 확인했다.
8. 보관함 제품을 45g당 200 kcal로 수정했다. 보관함은 200으로 바뀌고 기존 식사 합계는 696.5 그대로였다.
9. 검증용 식사에서 공식 식품 두 개를 제거했다. 기존 제품 사본 90g은 여전히 360 kcal였고 불포화지방은 “정보 없음”으로 표시되었다.
10. 보관함에서 검증용 제품을 삭제했다. 즐겨찾기는 0개가 되고, 식사에 남아 있는 제품 사본과 360 kcal는 유지되었다. 변경 저장 후 일일 불포화지방은 “미확인”으로 표시되었다.
11. 검증용 식사를 삭제하고 해당 날짜가 빈 기록·0 kcal로 돌아온 것을 확인했다. 오늘 날짜의 기존 365.5 kcal도 유지되었다. 검증용 제품과 즐겨찾기는 남기지 않았다.

긴 식사 편집창에서 제목과 저장 버튼이 화면 안에 유지되고 내용 영역만 스크롤되는 것을 확인했다. 화면 너비는 `min(760px, 100%)`이다. 스크린샷 캡처는 일부 DOM 변경보다 한 프레임 늦게 보일 수 있어 수치 검증에는 동작 직후의 실제 DOM 텍스트를 함께 확인했다.
