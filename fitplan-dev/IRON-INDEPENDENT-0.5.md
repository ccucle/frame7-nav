# FORMDAY v0.5.0 — 독립 웨이트 시스템 1차 적용

사용자 확정 정책(2026-11-23):
- 웨이트는 기존 「새 일정 등록」과 별개로 IRON MODE에서 시작.
- 루틴 제작·프로그램(요일 고정/순환)·실제 운동 세션을 별도 저장.
- 자유 운동: 완료 후 새 루틴 저장 여부 선택. 기존 루틴 반영은 별도 사용자 확인.
- 활성·일시정지·임시 보관 합계 최대 1세션.
- 임시 보관 자동 삭제 없음. 마지막 저장 후 24시간이 지나면 경고만 표시.
- 정상 완료 / 부분 완료 별도 구분. 확정된 세션만 캘린더 날짜에 읽기 전용 표시.
- 순환형은 프로그램의 예상 루틴을 정상 완료한 경우에만 다음 차례로 이동.
- **추가 비용 0원**, 기존 캘린더/웨이트 기록 절대 삭제·덮어쓰기 금지.

## 구현 범위
- 신규 독립 저장소 키 formday_iron_independent_v1, 스키마 v1. 기존 formday_calendar_proto_v1 키는 그대로 유지.
- IRON MODE 내 루틴, 프로그램, 운동 진행, 세트 입력과 휴식 타이머, 확정 기록, 캘린더 투영.
- 독립 저장소의 저장 오류와 다른 탭 변경 충돌 감지. 이전 raw 1개 localStorage 백업.
- IRON MODE JSON 내보내기 / 가져오기 별도 제공. 기존 무료 백업 다이얼로그에서 두 저장소의 백업이 별도임을 명시.
- 유산소·식단·체중·기존 웨이트 일정은 기존 캘린더에서 편집 가능. 새 일정 등록에서는 신규 웨이트 선택을 제외.
- Google Auth 연결은 로그인 확인만, Firebase Firestore 쓰기 및 데이터 업로드는 아직 사용하지 않음.
- 사용자의 건강 데이터는 GitHub/서버에 전송하지 않음.

## 테스트 범위와 주의
- 저장 시 리비전 충돌, 임시 보관 시간 제외, 부분 완료/정상 완료, 순환형 진도, 루틴 수정 시 과거 기록 보존.
- JSON 백업 포맷 검증, 유효성 없는 데이터 거부, 계정 동기화로 오해하지 않도록 UI 문구 표시.
- 실제 iPhone Safari 및 두 기기 간 동기화는 별도 검증 필요. 브라우저 저장소 삭제 시 복구를 보장하지 않으며, JSON을 클라우드에 수동 보관해야 함.
- 분리 이전에 작성한 기존 웨이트 기록은 '이전 웨이트 기록'에서 유지되며, 자동 이전/중복 표시나 자동 통합은 수행하지 않음.
- 완료된 운동 세션 수정 UI, 자동 추천, 고급 루틴 복제 및 완전한 클라우드 동기화는 아직 미구현.
